# Источники данных

## 1. Тестовые меши (уже скачаны) — `data/raw/test_models/`

Небольшие классические тестовые 3D-модели, скачанные из репозитория
[alecjacobson/common-3d-test-models](https://github.com/alecjacobson/common-3d-test-models)
(агрегатор оригинальных моделей Stanford 3D Scanning Repository, Blender и др.,
с указанием источника в README репозитория). Пригодны для локальной отладки
геометрических операций, mesh-редактирования, пайплайна извлечения/переноса
геометрии — **но не являются multi-view сценами** и не подходят напрямую для
обучения/оптимизации 3D Gaussian Splatting (для этого нужны калиброванные
фотографии сцены, см. раздел 2).

| Файл | Формат | Размер | Комментарий |
|---|---|---|---|
| `stanford-bunny.obj` (+ `.png`) | OBJ | ~2.3 МБ | классическая тестовая модель, органическая геометрия без резких граней |
| `spot.obj` (+ `.png`, `_texture.png`) | OBJ + UV-текстура | ~0.5 МБ | текстурированная модель коровы "Spot" (Keenan Crane), хороша для тестов текстурного редактирования |
| `cow.obj` (+ `.png`) | OBJ, **без реальной UV-текстуры** | ~0.26 МБ | лёгкая модель, но пригодна только для нетекстурного (normal-based) окрашивания — см. оговорку ниже |
| `suzanne.obj` | OBJ | ~48 КБ | стандартная "обезьяна" Blender, самая лёгкая модель, для быстрых smoke-тестов |
| `teapot.obj` | OBJ | ~0.2 МБ | классический Utah Teapot, объект с чёткими примитивными формами — удобен для проверки точных геометрических правок (digital twin сценарий) |
| `armadillo.obj` | OBJ | ~4.5 МБ | сложная органическая геометрия высокого разрешения, стресс-тест производительности |
| `cheburashka.obj` (+ `.png`) | OBJ, **без реальной UV-текстуры** | ~0.45 МБ | модель персонажа (Ilya Baran), узнаваемый объект для демонстрации семантических правок, но окрашивание — только normal-based |

⚠️ **Важная оговорка про `.png`-файлы репозитория** (обнаружено эмпирически при
разработке `scripts/generate_sample_gaussian_ply.py`): верхнеуровневые `spot.png`,
`cow.png`, `cheburashka.png` — это **превью-рендеры** модели для галереи GitHub,
а НЕ развёртки в UV-пространстве, и сэмплирование по UV-координатам с ними даёт
бессмысленные цвета. Настоящая UV-текстура нашлась только для `spot` — она
запакована внутри `spot.zip` как `spot/spot_texture.png` и уже извлечена в
`data/raw/test_models/spot_texture.png`. У `cow` (внутри `cow.zip` — только
`.ply` с, предположительно, per-vertex цветом) и `cheburashka` (внутри
`cheburashka.zip` — только `.off`, без текстуры) настоящей UV-текстуры в
репозитории нет вовсе. Правило в коде: доверять только файлам вида
`<имя>_texture.png` рядом с мешем; при отсутствии — красить по нормалям.

Источник репозитория: MIT/permissive-подобная агрегация, оригинальные модели —
общественное достояние/учебные модели Stanford Computer Graphics Laboratory
и Blender Foundation. Перед использованием в финальном тексте диссертации
проверить и указать точный source/license каждой модели по
`https://github.com/alecjacobson/common-3d-test-models/blob/master/data/README.md`.

## 2. Датасеты для полноценной 3DGS-реконструкции (нужно скачать отдельно, большие)

Эти датасеты содержат калиброванные многоракурсные фотографии реальных сцен
(с позами камер, обычно через COLMAP) и являются стандартными бенчмарками в
статьях по 3D Gaussian Splatting. Размер — от сотен МБ до нескольких ГБ на
сцену, поэтому не включены в репозиторий — скачивать по необходимости на
этапе `experiments/01_baseline_3dgs_reconstruction`.

- **Mip-NeRF 360** — 9 сцен (bicycle, garden, stump, room, counter, kitchen,
  bonsai, flowers, treehill), реальные сцены с полным обходом камеры вокруг
  объекта. Официальная страница проекта: https://jonbarron.info/mipnerf360/
  **Скачано:** прямая ссылка `http://storage.googleapis.com/gresearch/refraw360/360_v2.zip`
  (12 535 427 936 байт, все 9 сцен вместе, без логина). Извлечена только
  `bonsai/` → `data/raw/mipnerf360_bonsai/` (292 фото + `sparse/0/*.bin`
  COLMAP-модель + готовые `images_2/_4/_8`; архив после извлечения удалён,
  не хранить в git — см. `.gitignore`). Используется как первая baseline-сцена
  для `experiments/01_baseline_3dgs_reconstruction/`.
- **Tanks and Temples** (подмножество truck, train) — используется как
  стандартный бенчмарк в оригинальной статье 3D Gaussian Splatting. Страница
  проекта: https://www.tanksandtemples.org/
- **Deep Blending** (drjohnson, playroom) — используется как третий бенчмарк
  в оригинальной статье 3DGS.
- **NeRF Synthetic (Blender dataset)** — синтетические сцены (lego, chair,
  hotdog, ficus, drums, materials, mic, ship) с идеальными позами камер, без
  шума реальной съёмки — удобны для контролируемых экспериментов и как
  "простой" тестовый случай. Часто распространяется вместе с материалами
  оригинальной статьи NeRF (Mildenhall et al., 2020).
- Официальный репозиторий реализации 3DGS с инструкциями по датасетам:
  https://github.com/graphdeco-inria/gaussian-splatting

> Перед скачиванием проверить актуальные ссылки и условия лицензии на
> момент использования — ссылки на подобные исследовательские датасеты со
> временем переезжают.

## 3. Дополнительные источники для собственных "digital twin" сцен

Для сценария digital twin имеет смысл отдельно отснять/сгенерировать 1–2
собственные сцены небольшого физического объекта (например, стол, стул,
техническое устройство) с точными эталонными размерами — чтобы иметь ground
truth геометрию для расчёта метрик геометрической точности
(Chamfer/Hausdorff distance) в главе 7 методологии. Способ съёмки и
инструмент (телефон + COLMAP / Polycam / RealityCapture) — выбрать отдельно.

## 4. Готовые примеры облаков гауссиан (для быстрой обкатки вьюера/пайплайна редактирования)

### 4.1 Синтетическая заглушка (собственная генерация)

`scripts/generate_sample_gaussian_ply.py` сэмплирует точки на поверхности
`spot.obj` (окраска — из настоящей UV-текстуры `spot_texture.png`, см.
раздел 1) и сохраняет их как `.ply` в формате 3DGS (`save_gaussian_ply`,
`src/viewer/gaussian_ply_io.py`) — по умолчанию в
`data/raw/test_models/sample_gaussians.ply` (не хранится в git, см.
`.gitignore`; перегенерировать командой из `scripts/README.md`). Это не
настоящая обученная 3DGS-сцена (нет вида-зависимого цвета, ориентации
эллипсоидов и т.п.), а инженерная заглушка для проверки `src/viewer/` до
готовности baseline-пайплайна обучения (`experiments/01_baseline_3dgs_reconstruction/`).

### 4.2 Настоящие обученные 3DGS-сцены — скачаны и проверены на вьюере

Все три ниже — **реальный** вывод официального пайплайна обучения 3DGS
(та же схема полей `.ply`, что описана в `src/viewer/gaussian_ply_io.py`),
не синтетика. Не хранятся в git (см. `.gitignore` — `data/gaussian_scenes/`
целиком исключена), перескачать по ссылкам при необходимости.

| Папка | Источник | Категория | Размер | Лицензия |
|---|---|---|---|---|
| `data/gaussian_scenes/train_tanksandtemples/point_cloud_iter7000.ply` | [Voxel51/gaussian_splatting](https://huggingface.co/datasets/Voxel51/gaussian_splatting) (HF), сцена `train` (Tanks & Temples) | транспорт/уличная сцена | 176 МБ, 741 883 гауссиан | Apache-2.0 |
| `data/gaussian_scenes/luigi/luigi.ply` | [dylanebert/3dgs](https://huggingface.co/datasets/dylanebert/3dgs) (HF), `luigi/luigi.ply` | игрушка/фигурка (объект) | 0.97 МБ, 14 526 гауссиан | не указана явно в репо — уточнить перед использованием в финальном тексте |
| `data/gaussian_scenes/bonsai_sfm_pointcloud/input.ply` | [dylanebert/3dgs](https://huggingface.co/datasets/dylanebert/3dgs), `bonsai/input.ply` | сырое SfM-облако точек (не гауссианы: только `x,y,z,normal,rgb`) — проверяет fallback-ветку загрузчика для "обычных" `.ply` без полей 3DGS | 5.4 МБ, 206 613 точек | не указана явно — уточнить |

Практический вывод при тестировании (важно для digital twin/оценки
качества): у реальных обученных сцен (`train`) часть гауссиан — это "хвост"
далёких/фоновых точек (SfM-шум, недообученные ранние итерации), из-за чего
~50% гауссиан лежат в радиусе ~2.6 от медианного центра, а 90-й перцентиль
расстояния — уже ~21, при полном экстенте сцены на два порядка больше. Это
и заставило переделать автокадрирование камеры в `src/viewer/app.py` на
устойчивую к выбросам оценку (медиана + перцентиль расстояний), см. историю
изменений — наивный bounding-box давал почти пустой кадр.

### 4.3 Другие источники для просмотра/скачивания (не скачивались — требуют браузера/логина или очень большие)

По категориям, как просил пользователь — люди, объекты, сцены:

- **Люди / персонажи:**
  - [Sketchfab, тег "gaussian"](https://sketchfab.com/tags/gaussian) и [тег "splat"](https://sketchfab.com/tags/splat) — большая подборка CC-BY/CC0 3DGS-моделей, включая статуи людей (например, "Statue of Man under Tree"), сканы фигур и т.п. **Важно:** сам файл скачивается только через браузер с логином в Sketchfab — их API отдаёт архив только авторизованным запросам (`Authentication credentials were not provided`), анонимный `curl` не работает.
  - [alvinliu0/HumanGaussian](https://github.com/alvinliu0/HumanGaussian) (CVPR 2024, text-driven 3D human generation) — авторы выложили галерею готовых `.ply` synthetic-аватаров (не сканы реальных людей, а генерация по тексту) на SharePoint-папке CUHK, ссылка в README репозитория. Не скачивалось (папка рассчитана на ручной браузерный доступ).
  - Датасеты вроде THuman2.0/DNA-Rendering (реальные сканы людей для human-rendering статей) обычно требуют подписания лицензионного соглашения — не проверялось в рамках этой сессии.
- **Объекты/вещи (разнообразные категории):**
  - [GaussianWorld/omniobject_3dgs](https://huggingface.co/datasets/GaussianWorld/omniobject_3dgs) (HF) — конвертация [OmniObject3D](https://omniobject3d.github.io/) в 3DGS, >200 категорий повседневных вещей (`apple.zip`, `backpack.zip`, `fork.zip`, `guitar.zip` и т.д.), размер от ~13 МБ до нескольких ГБ на объект. **Проверено: доступ ограничен** (`Access to dataset ... is restricted. You must have access to it and be authenticated`) — нужен аккаунт HF и одобренный запрос доступа.
  - [dylanebert/3dgs](https://huggingface.co/datasets/dylanebert/3dgs) — помимо `luigi.ply`, содержит полноценные `point_cloud.ply` (7k/30k итераций) для `bonsai`, `bicycle`, `stump` (Mip-NeRF 360, помещения/сад с бытовыми объектами) — публично, без логина, но крупные (270 МБ–1.45 ГБ на файл).
  - [SuperSplat / superspl.at](https://superspl.at/) — платформа PlayCanvas для редактирования/публикации 3DGS; есть отфильтрованная галерея сцен, помеченных автором как "Downloadable" (CC-лицензии), но публикуются в сжатом формате `.sog`/`.ply` через веб-интерфейс — требует браузера, не проверялось программным скачиванием.
  - [Polycam explore](https://poly.cam/explore) — галерея пользовательских сканов (включая gaussian splats) с LiDAR/фото, часть помечена как свободно скачиваемая — тоже только через браузер/кнопку "Download".
- **Сцены/помещения (для контекста, не для скачивания в этом сеансе):**
  - `GaussianWorld/*` на HF — большая серия предобработанных 3DGS для ScanNet, ScanNet++, Replica, Matterport3D, HyperSim, 3RScan (indoor scene understanding бенчмарки) — публичность у разных репо разная, часть открыта (например `GaussianWorld/scannet_mcmc_3dgs_preprocessed`), не скачивалось из-за размера/оффтопика для целей просмотрщика.

> Такие файлы (за пределами официальных бенчмарков 3DGS-статьи) не являются
> частью научного бенчмарка сравнения и должны использоваться только для
> инженерной проверки/демонстрации вьюера, не для финальных экспериментов
> диссертации.
